# 采集管线与岗位池

## 使用入口

网页「岗位库 → 新建采集」与 WorkBuddy 的 `collection create --input FILE` 调用同一管线。每轮条件是不可变快照，用户修改求职配置不影响正在进行的采集。BOSS 为当前唯一实现的平台；其余平台不能提交。

```text
城市 × 关键词 × 页码 → 单页列表 → 平台/岗位 ID 去重
                                 ↓
                  公司 / 标题 / 实习 / 月薪预筛
                                 ↓
                   通过的候选 → 缺少正文才补详情
                                 ↓
                  核对岗位 ID → JD 排除词 → SQLite
                                 ↓
                         WorkBuddy 评分与话术
```

借鉴 BossHunter 的分层处理和岗位池流转设计，代码为本项目独立实现。这里继续使用用户正常登录的浏览器插件，不使用 BossHunter 的 CDP / 自动化浏览器。不会从文档中自动执行任何命令。

## 参数与请求边界

- `requestId`：每轮唯一，重复提交同号同条件返回原任务；同号不同条件拒绝。
- `platform`：目前为 `boss`。
- `keywords`：1–10 个关键词。
- `cities`：1–10 组 `{name,code}`；`code` 必须是已核实的 9 位字符串，不推测城市编码。
- `maxPages`：每城市 / 关键词组合 1–3 页，默认 1；仍是一次站点任务仅一页，不合并突发请求。
- `detailLimit`：整轮最多 0–30 个详情，默认 5；0 表示只采列表。已有验证 JD 复用。
- `requestBudget`：本轮总预算 1–100，默认 20；搜索页计 1，详情内部先刷新新鲜列表、再取正文，保守计 2。预算在派发前保留，失败不退回；未发出的候选不消耗预算。不是日配额或站点许可。
- `filters`：`blockedCompanies / titleExcludes / jdExcludes` 为字符串数组；`salaryMin / salaryMax` 为月薪 K；`excludeInternships / filterUnknownSalary` 为布尔值。条件越早判断，越能减少不必要的详情请求。

明确的月薪区间才用于数值过滤。日薪、年薪、面议、字体私用区字符不会猜数字；默认保留未知薪资，开启 `filterUnknownSalary` 才过滤。薪资上限和下限按区间是否相交判断，不把 13 薪折算成月薪。JD 排除词只在验证正文后判断。

## 串行与断点

单轮按城市、关键词、页码串行搜索，随后补充通过预筛的候选详情。任务之间沿用服务 180 秒默认冷却，不承诺避免风控。搜索必须传递真实页码；同一组合的岗位 ID 集合重复就停止该组合，重复页不计扫描数和已完成断点。空页同样标为结果不足。`hasMore=false` 则正常结束该组合。

`collection list` 返回每轮状态、阶段、已完成页面、候选队列及新增 / 重复 / 过滤 / 详情补齐 / 复用计数。过滤记录最多保留最近 200 条，含可解释原因。原始响应、Cookie 和关联令牌均不保存。

- `pause`：取消尚未领取的站点动作；已派发的允许回报结果并记录断点，不派发后续任务。
- `resume`：仅在用户确认连接与网站状态正常后，从最后完成页续采，不重跑已完成页面。
- `cancel`：取消后续计划，已派发动作不能撤回；结果仍可落库。
- 重启：管线暂停。已领取而未回报的任务为 `uncertain`，必须先人工核实并用原有 `resolve` 结案，再恢复插件和管线；不能以超时为由重发。
- 收集期间占用浏览器通道，普通采集计划和发送队列不会插队。暂停且无在途任务后释放通道。

检查点与本轮过滤结果使用 SQLite 事务一起提交；入队动作和预算保留同样一次提交。评分 / 生成话术由 WorkBuddy 执行，服务不会主动唤醒 AI。

## 岗位池

`pool search --input FILE` 对平台、关键词、城市、阶段、最低分、月薪区间进行本地筛选，按最新入库、匹配分或月薪上限排序；默认每页 15 条。`%`、`_` 按普通字符搜索，不是 SQL 通配符。状态统计是全池统计，列表计数则对应当前筛选。

状态由岗位内容和草稿状态共同推导：待详情 → 待 AI 审阅 → 待确认话术 → 发送队列；另有页面已出现、待核实、已过滤、已跳过、回收站。生成话术不会自动批准发送。

`pool action` 支持 `skip / reconsider / archive / restore`，携带每条的 `sourceKey` 和 `poolRevision`；任意条目版本不符，整批回滚。归档要求用户确认，软删除保留身份及历史，重采仍算重复；恢复不发消息，也不会把旧草稿自动批准。重新审阅使其回到待评分，需 WorkBuddy 重新生成。已发送、发送中及待核实条目不能回退或归档。没有永久删除入口。

`pool history` 返回该岗位最近 100 条采集、详情验证、评分、过滤、跳过与回收记录。SQLite 兼容增加 `job_events` 表，不重建或清空已有数据。历史只记录本版开始发生的事件。

## 当前边界

- 无跨平台或相似标题去重；只按平台及岗位 ID 去重。
- 无新的 DOM 采集器或字体反解；现有会话接口失败就暂停。
- 列表排序为网站默认；网页的最新 / 分数 / 薪资排序只作用于本地岗位池。
- 达到预算或详情上限后为部分完成，剩余候选保留在池中；可由下一轮采集或单岗详情入口继续，不暗中扩额。
- 自动发送规则沿用 [工作台](workbench.md)，与采集授权分离。
