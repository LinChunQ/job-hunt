# 本机求职工作台

`setup` 启动服务后，`ui` 打开已有服务时，均通过系统默认浏览器打开本机页面。不会启动自动化浏览器、调试端口或招聘页面。开发和无界面环境用 `--no-open`；CLI 始终返回不带凭证的普通地址。

自动连接使用 60 秒有效、仅一次的片段凭证交换；交换后立即移除片段。配对密钥只留在页面内存，不写 localStorage、sessionStorage、日志或 CLI 报告。刷新后可让 WorkBuddy 再运行 `ui`，也可输入本机配对码。不要把带启动片段的地址分享给他人。

## 页面功能

- 概览：岗位数量、待补正文、待审阅话术及本机连接状态。
- 求职配置：关键词、城市、月薪上下限（K，税前）、经验、学历、办公方式、已确认简历事实与备注；版本冲突会拒绝覆盖。
- 岗位库：采集进度、阶段标签、平台/城市/月薪/分数筛选、排序和分页；详情抽屉展示 JD、招聘人、来源及处理记录；支持批量跳过、重新审阅、回收与恢复。新建采集参数和断点规则见 [采集管线](collection-pipeline.md)。
- 话术审阅：编辑、保存、复制、跳过、勾选；未保存正文不能加入批次。轮询不丢弃未保存修改。
- 发送队列：每批最多 30 条。逐条执行、暂停、取消未发条目、不确定条目人工结案。所有状态持久化于本机 SQLite。

## 自动识别与发送（开发预览）

默认流程无需人工逐项标记。插件在已授权聊天页用站点适配器定位当前会话、公司、岗位、招聘人、输入框、发送按钮和消息记录区域。当前会话不匹配时，仅能选择已经存在且唯一匹配的会话行。岗位 ID 存在时必须一致；公司、岗位和招聘人必须精确匹配。多个候选、缺字段或页面结构变化均暂停。

尚未建立的聊天目前需要用户先在网站打开；本版不会从详情页自动发起新沟通，不会直接调用未知消息接口。聊天新开标签页时，仍由用户在插件重新连接授权。人工标记工具仅作页面诊断，并非自动发送的前提。

用户在工作台审阅公司、岗位、招聘人及最终正文，勾选确认后才创建发送授权。派发前先落盘锁定正文与状态，随后重新检查真实 DOM 节点，填入、读回并只点击一次发送。连续条目至少间隔 30 秒，这是本地队列限制，不能保证网站接受操作。

输入框清空且消息区域出现新节点中的精确正文时，记录为 `sent_observed`（页面已出现），不声称平台送达。点击后超时、失联、页面切换或进程重启均记录 `send_uncertain` 并暂停。人工结案只取消重试资格，不会自动重发。

自动发送使用虚构 DOM、隔离 SQLite 与本机 HTTP 测试；真实 BOSS 页面结构和发送流程仍需用户验收。升级后需重载扩展、重新连接，不应把单元测试通过当成网站已验证。

## 升级与暂停

从 0.1.x 更新代码后，确认无正在执行的任务，再由 WorkBuddy 停止旧服务并重新运行 `setup`；旧进程不会因替换代码自动升级。`SERVICE_VERSION_RESTART_REQUIRED` 表示服务仍在运行旧版本。扩展管理页也需手动重载新版插件并重新连接授权。

暂停或取消只阻止后续动作，已经派发到标签页的动作仍可能完成。取消后不会重新入队；结果未知时仍保留待核实状态。
